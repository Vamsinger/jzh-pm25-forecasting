# A：空气质量清洗与样本构建

## 我做了什么

这一部分把五百多万行空气质量记录整理成所有模型共用的逐小时数组。数组从 2015 年 1 月 1 日 00:00 开始，到 2018 年 12 月 31 日 23:00 结束。站点只保留训练期有 PM2.5 真值、同时拥有经纬度的站点，共 212 个。

没有观测的位置仍然是 `NaN`，不会把缺失值误当成 0。同一站点、同一小时若出现多行，程序会按污染物取非空值均值。实际审计没有发现这种重复。

## 怎样运行

在 `our` 目录执行：

```powershell
python A/prepare_airquality.py
python A/make_example.py
python A/plot_data_quality.py
python A/validate_airquality.py
```

第一条命令生成模型共享缓存，后三条分别生成真实样例、数据质量图和核验报告。

## 交给其他成员的内容

- `../cache/A/air.npy`：形状为 `[35064, 212, 6]`，通道顺序是 PM25、PM10、NO2、CO、O3、SO2。
- `../cache/A/stations.csv`：数组第二维对应的站点顺序和空间信息。
- `../cache/A/train_statistics.json`：只用 2015—2016 年数据计算的均值、标准差和有效数。
- `air_dataset.py`：输入起报小时索引，即可取得过去 48 小时历史、未来 24 小时 PM2.5 标签和缺失掩码。

训练、验证、测试标签分别使用 2015—2016、2017、2018 年。`split_origins()` 保证未来 24 个标签完整落在对应分区。验证和测试的第一个起报时刻可以使用上一年最后 48 小时内的合法历史，因为这些历史在起报时已经可以获得。所有历史时间都不晚于起报时刻。

## 数据质量结论

212 个站点在四年内的 PM2.5 平均覆盖率约为 71.3%，中位数约为 86.9%。部分站点开始记录较晚或提前停止，因此最长连续缺口可能很长。训练模型时必须把缺失掩码一起交给模型，并且只能在有真实标签的位置计算损失和误差。

可人工检查的样例位于 `outputs/`。样例选择 2017 年 1 月 3 日 00:00 为起报时刻，并自动选择该窗口数据最完整的站点。`validation_report.json` 已将这 72 小时重新与压缩原表逐项比较。
